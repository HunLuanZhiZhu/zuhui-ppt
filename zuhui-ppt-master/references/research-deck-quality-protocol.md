# 学术论文组会内容与证据质量协议（强制）

> 适用于 `zuhui-ppt-master` 的全部七阶段管道。此文档补充现有 Swiss 排版规范，不新增布局，不替代源论文。发现冲突时：**源论文准确性、图表语义完整性、公式可解释性优先于装饰、密度与页数凑数**。

## 0. 四条不可绕过的原则

1. **理论不是配角**：方法型论文优先解释问题、符号、假设、目标函数、架构计算路径、复杂度与适用边界，再用有限实验证实关键主张。不要因为论文图多就每图一页。
2. **图形完整性是语义问题**：网页 `<img>` 能显示、`object-fit:contain`、无 CSS 溢出、PDF/PPTX 页数一致，都**不能证明**源论文图中的 (a)/(b) 或小面板没有在裁切阶段丢失。必须核对源图。
3. **公式必须自解释**：公式旁的**可见幻灯片正文**解释所有关键符号、上下标、集合、维度/取值范围、输入输出、核心计算方向及设计作用。讲稿中的解释不能替代屏幕上的解释。
4. **不虚报 QA**：只执行了静态检查就只能写“静态检查通过”；没做源图逐项对照、公式语义审查或整页 1920×1080 实际渲染，不得宣称“视觉全部通过”“已确认图完整”或自行给出 4.5+/5 分。

## 1. 内容预算：理论优先，证据精选

每篇论文单独建结构表，把每一页归类为：问题/背景、理论/机制/推导、实验/评估、局限/讨论、章节过渡。

- **方法/算法/AI 论文默认规划**：理论与机制约 50%–60%，实验/评估约 20%–35%，其余为问题定义、限制与讨论。这里是**启动规划的软预算**，不是强迫改变论文实质的通用硬比率；超出时必须在 `slide_plan` 解释原因。多篇论文分别计算，不用总比例掩盖其中一篇“实验堆叠”。
- 每张实验图必须回答：“它验证了哪个未被充分证明的主张？”不满足则和另一张相关小图合并，或移入备用材料，或舍弃。大图不自动获得整页资格。
- 给理论页安排不少于一个真实的**推理对象**：符号映射、张量流、公式推导、复杂度分析、可核对的最小计算示例或边界情形。禁止用“多写几个术语”充当理论深化。
- 多论文：每篇有自己的论文元数据、来源版本、方法论链和局限性；两篇之间必须有明显过渡页；最后跨论文比较只能比在相同评价口径下可以对照的概念，不能把不同数据集、硬件、调参预算、指标的数值直接算胜负。
- 组会仍遵守项目级“内容页 ≥30 / 讲稿 ≥30 分钟”，但**不能靠多放实验图、复制内容或放慢语速**满足。若无法产生足量实质内容，明确记录阻碍并停止通过对应 gate。

## 2. 源文件与版本锁定（多论文、译图）

- 为每篇建立 `paper_id`、原论文路径及版本（如 arXiv v1/v2）、译文 PDF 版本、页码系统、图号对应关系、主张所用实验版本。
- **译文 PDF != 原始排版 PDF**：翻译软件可能增加一层中文覆盖文本，使标签拥挤或遮住曲线；“导出 600 DPI”不代表原始内嵌图像真实有效分辨率为 600 DPI。对比原版与译版，记录中文字重叠/缺字/图轴被遮盖的问题。
- 图与表来自哪个版本必须明确。若图来自 v1、正文讲解来自 v2，逐个核对相关指标和面板是否变更；无法核对则在计划、页脚或讲稿中**显式提示版本不一致**，不得静默视作相同。
- “图例”是图内部用于辨认曲线/颜色/符号的说明，**必须保留**；“图注/图名/长篇解释”是图外的独立说明，用户要求去掉时应剔除。不得混淆二者。

## 3. 论文图的语义完整性：以“逻辑图号”为单位

在准备任何布局前，为候选图建立 `figure_manifest_vN.json`（字段可扩展）：

```json
{
  "paper_id": "tabiclv2",
  "source_version": "arxiv-v1-translation",
  "source_pdf": "paper_zh.pdf",
  "source_page": 4,
  "figure_id": "Fig.3",
  "expected_panels": ["a-accuracy", "a-entropy", "b-1", "b-2", "b-3", "b-4", "b-5", "b-6"],
  "included_panels": ["a-accuracy", "a-entropy", "b-1", "b-2", "b-3", "b-4", "b-5", "b-6"],
  "scope": "complete",
  "image_file": "assets/tabiclv2_fig3_complete.png",
  "used_on_slides": [37],
  "figure_legend_intact": true,
  "axes_intact": true,
  "caption_removed": true,
  "compared_with_source": true,
  "human_review_status": "pass",
  "review_note": "已与原始 Fig.3(a+b) 并排核对"
}
```

字段准则：

- `expected_panels` 由原始**完整逻辑图**确定，不靠已经裁坏的 PNG 推断。
- `scope="complete"` 时，`included_panels` 必须与预期面板集合相同，包含每个面板的图例、轴、单位、标签、箭头及关键连接。
- `scope="intentional-partial"` 时，必须填 `crop_reason`、`on_slide_scope_disclosure`、未保留的 `omitted_panels`、完整图的去向；幻灯片不得称其为“完整 Fig.3”，也不得用局部面板证明依赖遗漏面板的结论。
- “把同一逻辑图拆到两页”不是默认做法。只有当讲解确需分层、每页作用明确且**每页是完整的独立面板**时才允许。不能因裁剪错误将 37 页的尾部放到 38 页，再以“后续公式页”解释。
- 多面板需要同页时，优先从 PDF 恢复完整图并给主证据足量版面；过密时可将各**完整**面板分配给明确标注的独立页，而不是截断同一面板。
- 先检查 PDF 坐标裁剪，再检查导出图像，再检查幻灯片渲染。三者不能互相替代。

**必需源图对照表**（记录在 `visual_audit_report`）：

| 逻辑图号 | 原 PDF 页与版本 | 原始面板清单 | 截图面板清单 | 图例/坐标/边界 | 幻灯片页 | 人眼并排结果 |
|---|---|---|---|---|---|---|
| Fig.3 | p4 / 译文 v1 | a 左2图 + b 右6图 | 全部或声明子集 | 完整/缺失 | 37 | PASS/FAIL |

## 4. 公式可解释性：逐条“符号账本”

凡在幻灯片上展示的公式必须登记到 `formula_ledger_vN.json`：

```json
{
  "slide": 36,
  "formula_id": "QASSMax",
  "source_paper": "tabiclv2",
  "source_location": "Sec.3",
  "latex": "q'_{h,i}=q_{h,i}\\cdot s_{h,i}\\log n",
  "symbols": [
    {"token": "q_{h,i}", "meaning": "第 h 个注意力头的第 i 维查询分量", "domain_or_shape": "实数标量"},
    {"token": "n", "meaning": "训练集/上下文中的样本数", "domain_or_shape": "正整数"},
    {"token": "s_{h,i}", "meaning": "受查询调节的缩放因子", "domain_or_shape": "按论文公式定义"}
  ],
  "input_output": "输入查询与上下文长度，输出缩放后的查询",
  "why_this_formula": "维持长上下文下的注意力聚焦",
  "assumptions_or_limits": "需要与论文完整门控定义核对",
  "example_or_shape_trace": "说明固定查询时 n 增大产生的变化",
  "source_verified": true,
  "visible_explanation_verified": true
}
```

**这只是账本示例，不代表可以用简式代替论文完整 QASSMax 公式。所有公式必须与所选论文版本逐字/逐项核验。**

可见幻灯片上的最低要求：

1. 定义全部**非公知**核心符号及关键运算符，明确训练/测试区分、行/列维度、上下标含义，避免孤立的 `q`、`h`、`i`、`n`；
2. 明确输入→运算→输出，不可只写“引入门控提高性能”；
3. 对长公式拆分为“定义页 → 推导/机制页 → 验证页”，不要通过把字号压到 14px 以下解决；
4. 非平凡公式至少有一个形状追踪、边界情况或代入示例，示例可以是教学用但**必须标为示意计算**，不得冒充论文实验；
5. 完整推导和其他次要符号可进讲稿，但**不能把关键符号的首次定义全部放到讲稿**。

优先重点审查：先验拟合目标、行列注意力索引、分段常数密度、特征循环分组、目标感知嵌入、注意力缩放与门控、混合进位标签、分位数/针球损失。

## 5. 四道审查：绝不以“加载成功”冒充“证据完整”

1. **源 PDF → 资产审查**：展示原文 PDF 图形范围与导出图的并排对比，逐面板勾选；图片清晰度以真实文字可读、轴/图例清楚为准。
2. **资产 → HTML 审查**：浏览器 1920×1080 实际渲染；用盒模型检查拉伸/隐藏/越界，并用肉眼核对内容面板齐全。
3. **相邻页审查**：重点看“上一页未讲完的图被下一页带出来”、重复/断裂图例、重复证据、页标题和展示证据不一致。检查顺序至少包括每个图页及其前后各一页。
4. **理论可读性审查**：检查每个公式的符号账本与可见解释逐条对应；对科研新生做“10 秒定位符号、30 秒说出运算意义”的可理解性检查，不合格就拆页或补解释。

失败修复：源图错回到第 1 阶段，逻辑拆页错回到第 2 阶段，公式说明缺口回到第 2/3 阶段，渲染错回到第 4 阶段；重跑受影响的下游审查。用户已指出的缺陷必须成为下一版**回归清单**，逐条注明实际修复证据。

## 6. 交付与报告

- `audit_note`：每篇论文版本、全部候选逻辑图的面板映射、译图缺陷。
- `slide_plan`：逐篇理论/实验页预算、图的保留/合并/舍弃依据、公式页预定义。
- `visual_plan`：注册布局 S01–S22 与图形纵横比匹配、每张图的主张和摆放。
- `qa_report`：各检查项的 PASS/FAIL/NOT RUN，不能把 NOT RUN 写成 PASS。
- `visual_audit_report`：含逐图的原文→裁剪→演示三层核对、相邻页连贯性、公式可读性。
- `visual_score`：保留原有六维度和 4.5/5 阈值，但任何关键源图或公式解释失败都是**一票否决**；分数再高也不能交付。
- 对最终用户准确说明 HTML/PDF/PPTX 已生成与否、浏览器真实渲染范围、PPTX 是否截图版本，以及仍需人工核对之处。

### 自动校验的边界

`scripts/validate-swiss-deck.mjs` 继续负责 Swiss 注册布局与静态限制。若启用研究证据账本检查器，它只验证字段和面板清单是否一致；**不能确认像素真的包含该面板**。没有完成人工源图对照，`human_review_status` 必须是 `pending` 或 `fail`，整个“证据完整性”质量门不能算通过。
