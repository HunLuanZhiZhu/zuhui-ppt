## Claude Code 整体插件路径与运行约定

当此技能作为整个 `zuhui-ppt` 插件的一部分使用时，**本技能的所有仓库相对路径均相对于插件根目录**，不是用户当前工作目录：

- 资源及模板：`${CLAUDE_PLUGIN_ROOT}/zuhui-ppt-master/assets/`、`${CLAUDE_PLUGIN_ROOT}/zuhui-ppt-master/references/`；
- 关联技能：`${CLAUDE_PLUGIN_ROOT}/zuhui-ppt-<stage>/SKILL.md`，Claude Code 中技能名称带有 `zuhui-ppt:` 命名空间；
- 校验器：使用 `node "${CLAUDE_PLUGIN_ROOT}/zuhui-ppt-master/scripts/validate-swiss-deck.mjs" "ppt_vN/deck.html"` 和 `node "${CLAUDE_PLUGIN_ROOT}/zuhui-ppt-master/scripts/validate-research-ledgers.mjs" ...`（根据实际输出路径替换示意路径）。

`PROJECT_SLUG`、`VERSION`、`OUTPUT_DIR` 和原论文素材属于**用户项目工作区**，不能把输出写进插件安装目录。继续遵守主控对 HTML、图面板、公式账本、质量门和旧版本保留的规则。独立通过 Skills 安装器使用时，依然按原先工作区与同级技能目录的方式定位资源。



# 组会 PPT 视觉评分（Zuhui PPT Visual Score）

## 目标

为完成的演示 deck 提供独立、可复现的视觉质量评估。本子技能补充 `zuhui-ppt-qa`（负责结构合规），评估 deck 在现场观众面前是否真正好看且有效沟通。

## 项目参数

所有路径使用 `zuhui-ppt-master` 中定义的项目参数：

- `PROJECT_SLUG` — 论文短名，用于文件命名
- `VERSION` — 当前版本号
- `OUTPUT_DIR` — `ppt_v{VERSION}/`
- `VISUAL_REF` — 已批准旧版本 deck 的路径，或 `none`

## 与 zuhui-ppt-qa 的关系

`zuhui-ppt-qa` 回答：“deck 结构上是否正确？”（文件存在、数量一致、布局注册、无禁用短语）。

`zuhui-ppt-visual-score` 回答：“deck 视觉上是否有效？”（证据可读、图占主导、排版严谨、节奏吸引人、密度合适、观众能跟上）。

两者都必须在交付前通过。QA 是门槛；视觉评分是质量信号。交付阈值为 **4.5/5**。若视觉平均分低于 4.5/5，即使 QA 通过也必须迭代。4.0-4.4 分仅在用户明确批准后可接受；否则迭代。

## 评分维度（6 轴，每轴 1-5 分）

### D1 — 证据可读性

观众是否能在每张幻灯片上真正阅读并理解图和表？

| 分数 | 标准 |
|-------|----------|
| 5 | 所有图/表清晰、完整，在 2-3 米投影距离可读；坐标轴、图例和关键数字无需放大即可阅读；多面板图中最重要的面板占主导；图注紧贴且充分；所有数学公式正确渲染 |
| 4 | 大多数图/公式清晰可辨；1-2 页可通过裁剪、拆分或略微放大来改善 |
| 3 | 若干图需要眯眼才能看清；部分关键数据点或坐标轴标签需放大才能看见；或少数公式渲染为原始 LaTeX；或 CSS 裁剪隐藏了次要面板 |
| 2 | 多图在演示距离无法阅读；密集表格被缩进小槽；图例不清；或多个公式/面板被裁剪或未渲染 |
| 1 | 关键证据图太小、模糊或被裁剪到无法阅读；观众无法提取所声称的结果；或公式损坏 |

逐页检查：
- 图/表是否足够大，在 2-3 米观看距离能读出关键值？
- 坐标轴标签、图例和注释是否清晰？
- 所有面板、坐标轴、箭头、标签是否完全可见，还是 CSS `cover` 裁剪了内容？
- 布局是否与图的纵横比匹配（竖图 → 左右分屏；横图 → 全宽 hero）？
- 对于高密度/框架图，是否占据幻灯片面积的 60-75%？
- 标题尺寸是否适合证据页，为图/表留出空间？
- 若是多面板图，最重要的面板是否占主导？
- 图注是否紧贴图边缘，而非远远漂浮？
- 所有 `$$...$$` 公式是否渲染为数学公式，无可见原始 LaTeX 片段？

### D2 — 图文协作

每张幻灯片上图片与文字的关系是否遵循证据层级？

| 分数 | 标准 |
|-------|----------|
| 5 | 每个证据页都有一张主导图（占 55-80%）和一条窄解读轨（20-30%）；图注紧贴图边缘；最多 1-3 个指标 callout；证据周围无等权重框；文字引导阅读顺序而不重复面板标签 |
| 4 | 大多数页面遵循协作规则；1-2 页文字块略大、图注 detached，或本可用 70/30 却用了 50/50 |
| 3 | 若干页默认 50/50 图文分屏；部分图注远离图；解读块在视觉上与证据竞争；部分页面缺少指标 callout |
| 2 | 许多页面在应主导时仍对称分屏；文字重复图标签；解读比证据更抢眼；图注 detached 或缺失 |
| 1 | 图像是贴到页面上；无解读轨；文字与图像争夺注意力 |

逐页检查：
- 图是否占据幻灯片面积的 55-80%？
- 解读轨是否窄（不是 50/50 分屏）？
- 图注是否紧贴图边缘？
- 是否有 1-3 个指标 callout（而非许多等权重框）？
- 文字是否引导阅读顺序而不重复面板标签？

### D3 — 排版纪律

整份 deck 是否始终遵循 Swiss International 排版规则？

| 分数 | 标准 |
|-------|----------|
| 5 | 全为无衬线；字重阶梯正确（越大越轻）；中文标题字号合适；最小字号得到遵守；无双重内边距；处处使用双约束字号；每页微调（第二步）在不破坏规则的前提下提升可读性 |
| 4 | 基本正确；1-2 页字重或字号略偏；每页微调基本得当 |
| 3 | 若干页字重阶梯不一致；部分标题过大或过小；缺少或未充分进行每页微调 |
| 2 | 频繁违反字重阶梯；出现衬线字体；许多标题过大或过小；无每页微调迹象 |
| 1 | 无一致排版系统；混用衬线/无衬线；随机字号；无字重层级；无每页微调 |

逐页检查：
- 全为无衬线字体？（Swiss deck 上无衬线）
- 同一页上较大文字字重是否轻于较小文字？
- 中文标题是否在字号表范围内？
- 无低于 14px 的文字？
- 无双重水平内边距（canvas-card + body 内容都加 5vw）？

### D4 — 视觉节奏

Deck 是否在暗与亮、陈述与证据、密集与稀疏之间形成引人入胜的交替？

| 分数 | 标准 |
|-------|----------|
| 5 | 强烈节奏：暗色章节打破浅色证据；每 3-4 页一张 hero 页；布局多样性（25+ 页 deck 使用 8+ 种布局）；无 3 张及以上连续同主题页面 |
| 4 | 整体节奏良好；1-2 个章节可加入章节分隔；布局多样性足够 |
| 3 | 有些单调：长串浅色页无分隔；布局多样性勉强（25+ 页 deck 仅 5-7 种布局）；结构重复 |
| 2 | 单调节奏：许多连续同主题页面；布局多样性低（25+ 页 deck 少于 5 种）；deck 感觉重复 |
| 1 | 无节奏：全同一主题；全篇重复同一布局；视觉平淡 |

逐页检查：
- 是否每 3-4 张证据页后有一张暗色章节分隔页？
- 25+ 页 deck 是否至少使用 8 种不同布局 ID？
- 是否无 3 张及以上连续同主体结构幻灯片？
- 封面是否确立视觉基调？
- 结尾是否提供令人满意的收束？

### D5 — 内容密度

每张幻灯片是否都有意义地填充，既不过度拥挤也不过于稀疏？该维度权重更高，因为稀疏幻灯片是反复出现的失败模式。

| 分数 | 标准 |
|-------|----------|
| 5 | 每个非过渡页都有 3-5 个具体信息点；顶部/中部/底部锚点存在且充实；密集证据页使用图 hero 加增值解读轨；无单句或空卡片；无无结构空白；文本主导页有 4-5 条具体要点或 3+ 实质性卡片；deck 感觉始终经过 authored，而非 padded |
| 4 | 大多数页面满足密度标准；1-2 页可添加额外指标 callout、对比或实质性句子以达到“5” |
| 3 | 有些稀疏页：少数页面仅 1-2 个信息点、小图被遗弃在空白中，或少数单句卡片；或部分页面略拥挤；密度不一致 |
| 2 | 多页稀疏且大片空白；或过多拥挤页；单句卡片常见；证据页缺少解读轨；页面缺少实质性内容 |
| 1 | 许多空页或许多拥挤页；deck 感觉半成品；大多数卡片为空或仅一句话 |

逐页检查：
- 顶部锚点存在（kicker 或章节标签）？
- 主导中部块（证据图/表/claim 卡片）是否充实？
- 底部锚点（take-away 条、source 条、结论行）？
- 每个非过渡页是否至少 3 个具体信息点？
- 无单句卡片或空卡片？
- 无大片无结构空白？
- 无过度拥挤文本块（6+ 条密集要点）？

### D6 — 观众清晰度

非专家观众成员能否在 10 秒内跟上演示流程并理解每页要点？

| 分数 | 标准 |
|-------|----------|
| 5 | 每页都有结论式标题陈述观点；流程遵循演示逻辑；技术术语包装为 中文（English）；无独立英文短语；speaker notes 提供上下文 |
| 4 | 大多数页面有结论式标题；流程清晰；1-2 页仅列主题；英文术语大多已包装 |
| 3 | 若干页面标题仅列主题（“Method”、“Results”）；流程偶尔不清；部分独立英文术语；观众可能在某些部分迷失 |
| 2 | 许多页面标题通用；演示逻辑不明显；频繁独立英文；观众难以跟上 |
| 1 | 无叙事结构；标题仅为章节标题；大量独立英文；没有演讲者解释观众就无法跟上 |

逐页检查：
- 标题是否为结论式（陈述观点，而非仅列主题）？
- 若新手按顺序只读标题，能否 get 到故事？
- 技术英文术语是否包装为 中文（English）？
- 可见 slide chrome 中无独立英文标签？
- Speaker notes 是否提供章节间过渡上下文？

## 评分前的研究质量否决项

执行本技能之前必须已通过 `zuhui-ppt-visual-audit`，其报告中以下项目为 `PASS`：`source_figure_semantic`、`formula_readability`、`adjacent_slide_coherence`。没有核验则 `NOT RUN`，**不允许假定合格并启动“已通过”的评分结论**。

六轴框架和 4.5/5 阈值保持不变，但增加下列评分要点：

- **D1 证据可读性**：不仅检查图片清晰，还要检查原 PDF 所定义的完整子图/面板是否确实出现在资产与最终页中；禁止把源图中漏掉的半幅误判为“无 CSS 裁切”。
- **D2 图文协作**：图的数量和大小应服务必要主张；低增量的小图能同页组合或删除，不以“每张图都有一页”加分。
- **D5 内容密度**：密度是论文信息、推理和解释的密度，不是卡片、数字或实验截图的数量。方法型论文应检查逐篇理论/实验预算是否合理。
- **D6 观众清晰度**：所有关键公式应能在当前可见页面读懂：符号、上下标、变量的形状/范围、输入输出、因果/计算关系、示例或极限。单凭讲稿里的术语表不够。
- **相邻页**：若上一页展示了不完整 Fig.3(a)，下一页无逻辑地接 Fig.3(b) 的残片，即使每页都美观，也属于可读性失败。

**评分不得回避否决项**：无论总体平均分多少，源图语义缺失、关键公式无法理解、源论文版本错配或用户已明确指出的回归错误未修复，建议均为 FAIL；报告应列明问题与修复责任阶段，而不是报 4.5/5“优秀”后交付。

## 评分步骤

### 第一步 — 通过标准管道将幻灯片渲染为单页图片

**标准管道**（默认）：
1. **HTML → PDF**：使用 headless 浏览器（Chrome/Edge headless）将 HTML 打印为 PDF
2. **PDF → 单页图片**：使用 PyMuPDF 将 PDF 拆分为单张 PNG 图片（1920x1080，每页一张）
3. 创建按顺序排列所有幻灯片的 contact sheet。

若有渲染器：
- 遵循上述标准管道。

若无渲染器：
- 从 HTML 提取幻灯片结构（section 元素、data-layout 属性、文本内容、图片引用）。
- 创建结构 contact sheet，列出每页的布局、标题和资源引用。

在评分报告中记录使用的方法。

### 第二步 — 逐页评分

对每页，按 1-5 分评估全部 6 个维度。记录：

```
Slide N: [标题]
  D1 证据可读性: X/5 — [一句话理由]
  D2 图文协作: X/5 — [一句话理由]
  D3 排版纪律: X/5 — [一句话理由]
  D4 视觉节奏: X/5 — [一句话理由]
  D5 内容密度: X/5 — [一句话理由]
  D6 观众清晰度: X/5 — [一句话理由]
  Slide average: X.X/5
```

### 第三步 — 计算维度平均与总体分数

对每个维度，计算跨页平均分。然后计算总体 deck 分数为 6 个维度平均分的未加权均值。

```
Dimension averages:
  D1 证据可读性:    X.X/5
  D2 图文协作: X.X/5
  D3 排版纪律:   X.X/5
  D4 视觉节奏:           X.X/5
  D5 内容密度:         X.X/5
  D6 观众清晰度:        X.X/5

Overall deck score: X.X/5
```

### 第四步 — 识别弱页与关键修复

列出平均分低于 3.0/5 的所有幻灯片。对每页，指定最有影响力的单一修复：

```
Weak slides:
  Slide N (avg X.X): [最有影响力的修复]
  Slide M (avg X.X): [最有影响力的修复]
```

同时列出平均分最低的维度及改进它的首要建议。

### 第五步 — 与 VISUAL_REF 对比（如适用）

若 `VISUAL_REF` 指向已批准的旧版本，将当前 deck 的评分与该参考版本的视觉质量对比。记录哪些维度提升、哪些回退。

若无 `VISUAL_REF`，跳过此步。

## 分数解读

| 总体分数 | 操作 |
|---------------|--------|
| 4.5-5.0 | 优秀 — 按原样交付 |
| 4.0-4.4 | 仅在用户明确批准后可接受；否则迭代弱页和最低维度后再交付 |
| 3.5-3.9 | 需要改进 — 交付前迭代弱页和最低维度 |
| 2.5-3.4 | 重大问题 — 建议进行全面重设计 |
| 1.0-2.4 | 失败 — 从故事脊椎重建 |

## 输出

在 `{OUTPUT_DIR}/visual_score_v{VERSION}.md` 中撰写视觉评分报告，包含：

- 使用的评分方法（渲染截图 vs 结构提取），
- 逐页评分与理由，
- 维度平均分，
- 总体 deck 分数，
- 弱页及建议修复，
- 最低维度及首要建议，
- 与 `VISUAL_REF` 的对比（如适用），
- 通过/失败建议。

## 与 zuhui-ppt-master 管道的集成

本子技能在 `zuhui-ppt-qa` 之后、最终交付之前运行。更新后的管道为：

1. `zuhui-ppt-source-audit`
2. `zuhui-ppt-story-spine`
3. `zuhui-ppt-swiss-design`
4. `zuhui-ppt-triformat-export`
5. `zuhui-ppt-qa` — 结构门槛
6. **`zuhui-ppt-visual-audit`** — 源图/公式/相邻页视觉审查
7. **`zuhui-ppt-visual-score`** — 六维评分

若 QA 失败：先修复结构问题，再重新运行 QA。
若 QA 通过但 visual-audit 的关键质量门失败：先回溯源图、故事脊椎或视觉阶段修复，再重做审查；不允许仅通过主观打分掩盖。若 visual-audit 通过但评分 < 4.5：迭代弱页，然后重新运行视觉评分。未经用户明确批准，不要交付低于 4.5 的 deck。
仅当 QA、visual-audit 均通过且视觉评分 ≥ 4.5，并且用户反馈回归项均关闭，才允许按已完成交付。

## 交付规则

视觉评分报告必须存在，且总体分数必须记录在案，deck 才能被标记为已交付。若总体分数低于 3.5，在 QA 报告中明确将 deck 标记为“needs significant rework”。若分数低于 4.5，默认操作是迭代，而非交付。
