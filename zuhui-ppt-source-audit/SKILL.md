## Claude Code 整体插件路径与运行约定

当此技能作为整个 `zuhui-ppt` 插件的一部分使用时，**本技能的所有仓库相对路径均相对于插件根目录**，不是用户当前工作目录：

- 资源及模板：`${CLAUDE_PLUGIN_ROOT}/zuhui-ppt-master/assets/`、`${CLAUDE_PLUGIN_ROOT}/zuhui-ppt-master/references/`；
- 关联技能：`${CLAUDE_PLUGIN_ROOT}/zuhui-ppt-<stage>/SKILL.md`，Claude Code 中技能名称带有 `zuhui-ppt:` 命名空间；
- 校验器：使用 `node "${CLAUDE_PLUGIN_ROOT}/zuhui-ppt-master/scripts/validate-swiss-deck.mjs" "ppt_vN/deck.html"` 和 `node "${CLAUDE_PLUGIN_ROOT}/zuhui-ppt-master/scripts/validate-research-ledgers.mjs" ...`（根据实际输出路径替换示意路径）。

`PROJECT_SLUG`、`VERSION`、`OUTPUT_DIR` 和原论文素材属于**用户项目工作区**，不能把输出写进插件安装目录。继续遵守主控对 HTML、图面板、公式账本、质量门和旧版本保留的规则。独立通过 Skills 安装器使用时，依然按原先工作区与同级技能目录的方式定位资源。



# 组会 PPT 源文件审计（Zuhui PPT Source Audit）

## 目标

在设计任何幻灯片之前，创建一份可信的源文件清单。本子技能通过提取论文的真实证据对象来防止稀疏 deck：图、表、附录流程图、实现表、限制章节以及旧版本反馈。

## 项目参数

所有输出路径与命名使用 `zuhui-ppt-master` 中定义的项目参数：

- `PROJECT_SLUG` — 论文短名，用于文件命名
- `VERSION` — 下一个未使用的版本号
- `OUTPUT_DIR` — `ppt_v{VERSION}/`
- `VISUAL_REF` — 已批准旧版本 deck 的路径，或 `none`

## 精益操作模式

默认采用仍能产出可信源文件清单的最低开销工作流。

应做：
- 只阅读理解论文论点所需的源材料，
- 仅提取实际会出现在 deck 中的图/表，
- 先渲染低分辨率 contact sheets；仅对选定的图/表页渲染高分辨率，
- 仅裁剪会出现在 deck 中的资源，
- 采用两遍阅读策略：第一遍抓取元数据、摘要、标题、图例、表题；第二遍只读支持幻灯片所需的结果与方法页。

默认避免：
- 穷尽提取每一张图、页、图片、表格或补充材料，
- 除非 PDF 扫描或正常文本提取失败，否则不进行完整 OCR，
- 除非调试或复用需要，否则不保存完整原始论文文本，
- 当只有少数几页包含有用图片时进行全页高分辨率渲染，
- 仅为了预览而启动 GUI 应用或桌面自动化。

组会/文献汇报 deck 的硬性指标为 **总页数 ≥ 30 页、讲稿时长 ≥ 30 分钟**。因此源文件审计阶段就要判断论文是否具备足够证据支撑 30+ 页的深度讲解：

- 若论文内容充足，应提取 10-20 个候选图/表/流程图资源，以支撑多页证据页、方法细节页、消融分析页和限制讨论页。
- 若论文本身较单薄，应主动挖掘附录、补充材料、相关工作、实现细节和扩展讨论，为 story spine 提供足够素材，而不是通过重复或无关页凑数。

## 需检查的输入

- 原始论文 PDF。
- 翻译 PDF，尤其是当其中的图/表已被翻译时。
- 旧版本 deck：`.pptx`、`.html`、`.pdf`、脚本、截图、QA 报告。
- 用户反馈与硬约束。
- 仅在用户明确说明可用且相关时，才收集个人信息或演讲者元数据。

## 演讲者与论文作者元数据分离

源文件审计时必须同时提取两类元数据，并分别存放，避免混淆：

- **论文元数据**：标题、论文作者、作者单位、发表会议/期刊、年份、DOI/arXiv 链接等。这些信息必须从论文 PDF/HTML 原文提取。
- **演讲者元数据**：汇报人姓名、所在单位、组会日期、导师/组别等。这些信息来自用户提供的本次汇报场景，若用户未提供则使用占位符（如 `[演讲者姓名]`、`[演讲者单位]`、`[汇报日期]`）。

审计笔记中应明确区分上述两类字段，不得将论文作者直接当作演讲者。

## 强制源图与版本审计（新增）

执行主控 `references/research-deck-quality-protocol.md` 的源资产协议，输出 `figure_manifest_v{VERSION}.json`：

1. **按论文分区**：每篇给出独立 `paper_id`、标题、作者、发表信息、原版/译版 PDF 路径、版本标识（例如 arXiv v1/v2）、页码映射。翻译图与正文若跨版本，逐图/表核对指标与标签；无法核对写明不确定性。
2. **逻辑图号优先**：先在原 PDF 确认 `Fig.3` 由哪些 (a)/(b) 和小面板组成，再决定是否裁切、重排或舍弃。不得从已经裁坏的图反推原图边界。
3. **源资产三层核验**：原 PDF 完整图 → 导出 PNG/SVG → 演示所用组合图。对照四边界、面板、图例、轴、单位、箭头与连线。译文覆盖导致重叠/曲线遮挡需记录并回退更干净的来源，不要假定高 DPI 就是高有效清晰度。
4. **图内图例必须保留**；图外 `Fig. x | ...` 图注、长文字、页眉、页脚按用户需求去除。不得将 “图例”当成应剔除的“图注”。
5. 若仅采用一个有独立语义的完整子面板，明确 `scope=intentional-partial`、`included_panels`、`omitted_panels`、`crop_reason` 和幻灯片上的局部范围提示。不得让下一页接上前页遗漏的半幅曲线或半幅决策边界。
6. 对候选资源标注 `keep / combine / omit / backup` 以及原因。并非所有图都要出现在 PPT 中；理论解释页可以优先于低增量的实验图。

示例质量事故：一张源图同时包含 `Fig.3(a)` 的两条曲线与 `Fig.3(b)` 的六个决策边界，必须先把八个面板列全；仅保留曲线不能声称展示了“完整图3”。

## 翻译 PDF 规则

若存在翻译 PDF，即使不存在单独的翻译图片文件夹，也要假设其中的图/表可能已被翻译。

工作流：

1. 渲染低分辨率页面 contact sheets。
2. 识别包含关键图/表的页面。
3. 仅对选定页面以更高分辨率渲染。
4. 将翻译后的图/表裁剪进 `{OUTPUT_DIR}/assets/`；排除正文段落、图外图注、表题和周围论文文字；**保留图内部图例、坐标轴及必要标签**。
5. 创建裁剪 contact sheet。
6. 记录页码、裁剪文件名、图/表身份与预期用途。

不要把“如何解决英文图”放进最终 deck。解决方案是操作层面的：使用干净的图裁剪和本地说明。表格应从已核验文本重建为原生表格，而不是裁剪为截图。

当存在提取出的干净图片文件夹（如论文的 `images/` 目录）时，将其作为裁剪边界参考。优先使用这些干净图资源，而非包含说明或段落的大范围翻译 PDF 截图。

## 旧版本审计

对于每个旧版本（搜索工作区中的 `ppt_v*/` 目录），检查：

- 幻灯片数量，
- 视觉风格，
- 是否存在 Swiss International 风格，
- 图片尺寸与可读性，
- 稀疏页，
- 禁用 meta 内容，
- 缺失证据对象，
- PPTX/HTML/PDF 是否全部存在。

将用户批评视为验收标准，而非可选评论。若 `VISUAL_REF` 指向特定版本，则该版本为视觉黄金源。

## 密集提取方法论

本子技能采用内容优先的提取方法，内化了久经考验的论文到 PPT 工作流：

1. **扫描所有证据对象**：不要停在摘要和主图。检查表格、附录图、流程内部、部署足迹、对比表、失败模式、限制段落和实现细节。
2. **与源文件核对**：所有数字和论点必须与论文或翻译文本交叉核对。不要从任何外部参考借用示意性或幻觉指标。
3. **分类每个视觉对象**：判断每个证据对象是干净图裁剪（优先）、原生重建表格（用于清晰数值），还是应拒绝的宽泛截图（含正文/图外图注）。
4. **映射到幻灯片角色**：为每个视觉对象分配角色：cover、workflow、evidence、comparison、appendix、limitation。

## 源文件清单输出

在 `{OUTPUT_DIR}/audit_note_v{VERSION}.md` 中创建或更新一份简短审计笔记，包含：

- 源文件与路径，
- 论文元数据，
- 论文类型，
- 翻译 PDF 页面地图，
- 候选图/表及页码，
- 选定资源与裁剪文件名，
- 每个视觉对象是干净图裁剪、原生重建表格还是被拒绝的宽泛截图，
- 旧版本 deck 弱点（来自 `VISUAL_REF` 检查），
- 用户约束与禁用内容，
- 风险或缺失源材料。

## Asset Manifest 字段

对每个提取出的视觉对象：

- asset 文件名，
- 源 PDF 路径，
- 源页面，
- 已知图/表标签、逻辑图号与 expected_panels/included_panels，
- 原版与译版的版本号、页码映射，
- 裁剪范围与图外图注去除状态、图内图例保留状态，
- 原图并排检查的 human_review_status（pass/fail/pending），
- 裁剪方法，
- 幻灯片角色：cover、workflow、evidence、comparison、appendix、limitation，
- 质量备注：readable、dense but usable、needs full-slide placement 或 should be split。

## 质量门

以下条件满足前，不要标记本阶段完成：

- 有用的翻译图/表裁剪已存在，
- 包含段落或图外图注的宽泛裁剪已被拒绝，图内部图例已完整保留，
- 故事所需的论文表格已计划原生重建，
- 已检查裁剪 contact sheet，
- 旧版本失败点已明确，
- 证据丰富的附录/表格材料已纳入候选地图，但与论点无关的图已标为 combine/omit/backup，
- 关键逻辑图全部有面板清单及原图并排核验，跨版本差异已披露。
